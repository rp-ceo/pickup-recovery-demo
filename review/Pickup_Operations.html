    What the replay measures

    The examples include unusual failures on purpose. Times advance on a simulated clock. A production pilot would measure actual handoffs, collection scans and missed update deadlines.

    The first pilot sends a rebooking link after a verified miss. A shopper who writes back can ask about the times or choose by email. An unclear preference keeps the available choices open. A reported address or custody problem needs verification. This replay uses rules and example matching. In the command-line demo, an optional local model classifies replies those rules leave unresolved. The booking checks are the same in both modes.

    REVER documents preferred pickup ranges. Dates and availability here come from a simulated carrier. An unanswered booking goes to Support unless a carrier specifically supports checking that attempt. CreatePickup API
